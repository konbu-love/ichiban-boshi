# 描画担当への受け渡し仕様 v1.0

区分: 【実測】=監査スクリプトが数えた値 / 【方針】=GPT・ユーザー決定 / 【計算の目安】=見積り / 【未確認】=裏づけなし。
実データは、d3-celestial@0.7.35 と astronomy-engine を GitHub Actions で変換して作る。描画の試作は、実データが出るまで「ダミーデータ(実際の天文データではない)」と明記して使う。
最終的な軽量化の判断は Pixel 7a の実機テスト後におこなう(Actions上の速度と実機の速度は別)。

## 1. 恒星の採用ルール【方針】
- 通常の恒星は6.0等まで。星座線の構成に必要な星は、6.0等より暗くても例外として採用する(現時点でHIP 10826=6.47等の1つ【実測】)。等級は改変しない。
- 例外採用の星は、通常観測時は他の星と同じ視認条件(地点の限界等級)を適用する。星図モードでは線の構成点として表示する。
- 一番星の選択対象 = (星座線の構成星 ∪ 固有名のある6.0等以下の星) のうち、通常の視認条件を満たす星。例外採用の星も同じ条件。
- 候補は912星(6.0等以下が911、例外が1)【実測】。3.5等以下で候補から漏れる7星(HIP 32759, 32768, 36377, 45080, 46701, 48002, 56561)も昇格させる【実測】。
- 7.0等までの追加は初期版では行わない(容量は6.0等で軽量JSON gzip 63.6KB、7.0等で188KB【実測】。描画量で判断する)。

| --- | --- | --- |

| names.json | 固有名・日本語名 | `{"HIP": {"en": "...", "ja": "..."}}`。jaが無ければ省く(日本語名は279件、出典未確認) |

## 3. 線の頂点の対応規則(判断方法の記録)
1. 頂点の座標から0.05°以内の星を候補にする。頂点893個すべて、0.001°以内に星があった【実測】。
2. 候補が複数あるとき(24頂点)は、一番明るい星を採用する。
3. 明るさの差が0.5等未満の頂点(Dra, Ser, Tuc の各1か所)は、元データ(starnames.json)で次の順に確認する。
   - ベイヤー符号が付く星が1つだけなら、それを採用(basis=bayer)。
   - 固有名が付く星が1つだけなら、それを採用(basis=name)。
   - どちらでもなければ、暫定的に明るい方(basis=brightest, confirmed=false)。
4. 各頂点の採用結果と理由は、監査レポートの「複数星の頂点(全件)」に basis・confirmed・候補の命名つきで残る。
5. 近い方でなく明るい方に変わった頂点は5つ(HIP 69483, 43103, 63125, 71683, 102532)【実測】。

## 4. 計算の決定事項【実測+ドキュメント確認】
- 基準時刻 t0 は、太陽の「中心・大気差なし」の高度で決める。astronomy-engine の `SearchAltitude` がその定義で、-6°/-9°/-12°/-18° のすべてで検算が一致した(誤差0.005°以内)。初期値は -12°(仮)で、-6°/-9°/-12° を切り替えられるようにする。
- 恒星のJ2000座標は、日付の座標系へ回転してから `Horizon` に渡す(公式ドキュメントで、日付の座標系が必要と確認)。J2000のままでは北極星で高度が約0.1°、太陽で約0.3°ずれる【実測】。
- 見た目の空の明るさ(大気差を含む)は、基準時刻とは別の設定にする。
- 月は観測者基準の位置で描く。地心基準との差が約0.2°ある(2026-12-21 12:00 UTC、東京付近)【実測】。
- 地平座標の計算は1回約1.6μs(Actions上)【実測】。スマホでの速度は実機で確認する【未確認】。
- 極点では方位角が一意でない(返り値は有限の値)。極は初期版の対象外。

## 6. 計算モジュール `computeSky(site, date)` の返り値案
- 太陽高度、基準時刻t0、薄明の段階
- 各天体の高度・方位(方位は北0°で東回り。水平窓は左から右へ方位が増える)
- 月(位相・位相角・観測者基準の位置)、惑星(等級)
- 一番星の選択対象(天体ID・等級・選択できるか・その理由)、予想される最初の星のヒント

## 7. 保留(初期版には入れない)
