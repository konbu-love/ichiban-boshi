# 描画担当への受け渡し仕様(案 v0.2)

区分: 【実測】=監査スクリプトが数えた値 / 【方針】=GPT・ユーザー決定 / 【未確認】=まだ裏づけなし。
実データの生成は、監査で使った d3-celestial@0.7.35 と astronomy-engine を GitHub Actions で変換して行う予定(この仕様はその出力形式)。
描画の試作は、実データが出るまで「ダミーデータ(実際の天文データではない)」と明記して使う。

## 1. 恒星の採用ルール【方針】
- 通常の恒星: 6.0等まで。
- 例外: 星座線の構成に必要な星は、6.0等より暗くても採用(例: HIP 10826 = 6.47等)。等級は改変しない。
- 例外採用の星は、通常観測時は他の星と同じ視認条件(地点の限界等級)を適用する。つまり暗い空でなければ見えない。
- 星図モードでは、線の構成点として表示する。
- 一番星の選択対象 = (星座線の構成星 ∪ 固有名のある6.0等以下の星) のうち、通常の視認条件を満たすもの。例外採用の星も同じ条件。
- 明るい星(3.5等以下)で上に入らない星が7つある【実測】。選択対象に加える。

## 2. ファイル構成
| ファイル | 内容 | 形式 |
| --- | --- | --- |
| stars.json | 恒星(6.0等まで+例外) | `[HIP, raDeg, decDeg, mag, bv]` の配列。J2000、度。bv は無ければ null |
| names.json | 固有名・日本語名 | `{"HIP": {"en": "...", "ja": "..."}}`。ja は無ければ省く |
| lines.json | 星座線 | `{"Ori": [[hipA, hipB], ...]}`(HIP番号の組)。星座名は IAU 3文字 |
| constellations.json | 星座の名前・中心位置 | `{"Ori": {"ja": "...", "en": "...", "ra": 0, "dec": 0}}`(日本語名の出典は未確認) |
| mw.json | 天の川(簡略) | 2〜3層の多角形。赤経±180°の継ぎ目で分割済み。許容誤差0.25°で約2,700頂点【実測から推定】 |
| sites.json | 23地点 | id, 名前, lat, lon, IANA時刻系, 暗さクラスA〜E(ゲーム設定), 風景6種 |
| credits.json | 出典・ライセンス表記 | d3-celestial(BSD-3, Olaf Frohn)、astronomy-engine(MIT)ほか。未確認は未確認と明記 |

## 3. 線の頂点の対応規則【実測で確認した問題】
- 頂点の座標が二重星などで複数の星に重なるとき(24件)、許容誤差0.05°以内で「一番明るい星」を採用する。最近傍は使わない。
- 等級差が0.5未満の頂点は、人が確認する(例: Dra, Ser, Tuc)。
- 頂点は893個すべて、座標0.001°以内で恒星に一致した【実測】。

## 4. 計算モジュール(天文担当が出す)
`computeSky(site, date)` の返り値案:
- 太陽高度、基準時刻(h0 = -12° 仮。-6°/-9°/-12° を切り替え可能)
- 各天体の高度・方位(方位は北0°で東回り、水平窓は左から右へ方位が増える)
- 月(位相・位相角・観測者基準の位置)、惑星(等級)
- 一番星の選択対象(天体ID・等級・選択できるか・その理由)、予想される最初の星のヒント
- 恒星の J2000 座標は、日付の座標系へ回転してから地平座標にする(astronomy-engine の Horizon は日付の座標系を要求する。公式ドキュメントで確認済み)。J2000 のまま渡すと北極星で高度が約0.1°ずれる【実測】。

## 5. 未解決(確定していない)
- 太陽高度の検算で、-12°を探した時刻の高度が約0.5〜0.6°ずれる【実測】。原因は切り分け中。確認用のコードを足して再実行する。
- 月の観測者基準と地心基準の差: 確認スクリプトの不具合で未測定。修正して再実行する。
- 地点の座標: 取れていないのは西はりま天文台と三鷹(国立天文台)。下の候補を参照。
